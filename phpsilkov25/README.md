## Запуск на macOS з XAMPP

Відкрити термінал у корені репозиторію і виконати:

```sh
/Applications/XAMPP/xamppfiles/bin/php -S 127.0.0.1:8094 -t phpsilkov25
```

Якщо PHP доступний через PATH, можна використати `php -S 127.0.0.1:8094 -t phpsilkov25`.

Відкрити http://127.0.0.1:8094/index.php. Для зупинки сервера натиснути Ctrl+C у терміналі. GitHub Pages не виконує PHP: на GitHub доступні код і звіти, а програму потрібно запускати через PHP-сервер.

## Як перевірити

1. Натиснути «Додати нове завдання».
2. Вибрати пріоритет і надіслати порожню назву та опис: з’являться дві помилки.
3. Заповнити лише назву: після надсилання вона залишиться у полі, а помилка опису залишиться над формою.
4. Заповнити всі поля й натиснути «Зберегти»: завдання з’явиться у списку та `data.json`.
5. На сторінці створення відкрити «Перевірка POST» або «Перевірка GET», заповнити поля й надіслати: буде показано `var_dump()`, без додавання до списку.

Файл `data.json` має бути доступним для запису користувачу, від якого запущено PHP.

## Перевірка лабораторної №8

1. Відкрити `create.php` у звичайному режимі «Збереження».
2. Заповнити назву, опис і пріоритет; вибрати JPG або PNG до 2 МБ.
3. Натиснути «Зберегти»: перевірити повідомлення, зображення й `$_FILES`.
4. У VS Code розгорнути `uploads` та відкрити новий файл.
5. Повторити із файлом понад 2 МБ або неправильного типу: має з’явитися помилка.

Для демонстрації ліміту PHP можна запускати з `-d upload_max_filesize=3M -d post_max_size=4M` перед `-S`. Ліміт обробника залишається 2 МБ. Після успішного POST з файлом не оновлюйте сторінку з повторним надсиланням: для нового завдання натисніть «Збереження». Вивід `$_FILES` залишено для навчальної демонстрації.
